# Install identity & request signing contract (rr.install.v1)

**Status:** approved 2026-08-21 (plan: `~/.claude/plans/bro-i-thought-you-iridescent-charm.md`, W1/W2)
**Applies to:** backend worker (`backend.rr-admin-panel.workers.dev`), Pages Functions (`rr-admin-panel.pages.dev`), later `rr-api` on the NAS, and the desktop client ≥ 1.4.9.

## Why
The shared ingest key shipped in the client is public. Each install now owns an ECDSA P-256 keypair; the server stores only the public key. A leaked private key identifies exactly one install, which can be rate-limited and revoked.

## Registration
`POST /api/install/register` (worker; later also rr-api) — **unsigned**, rate-limited (5/min/IP, 3 new installs per HWID per day).

Request body (JSON, ≤ 4 KB):
```json
{
  "install_id": "6f1d2c9a-9b2e-4a5d-8d77-2f4e1c0a9b13",
  "hwid": "A1B2…32 hex…",
  "public_key": { "kty": "EC", "crv": "P-256", "x": "<base64url>", "y": "<base64url>" },
  "app_version": "1.4.9",
  "license_key": "optional"
}
```
- `install_id`: RFC-4122 GUID (C# `Guid.ToString("D")`), stored lowercase. Must equal the existing `rr.telemetry.install_id`.
- `public_key`: JWK of the P-256 public key (`x`,`y` base64url, 32 bytes each).
- Responses: `201 {ok:true, install_id, registered_at}` new; `200 {ok:true, install_id, registered_at}` same install + same key (idempotent); `409 {ok:false, error:"install_id already registered with a different key"}` → client generates a **new** install_id + keypair and registers again; `401` if the install is revoked; `400` on shape errors; `429` rate limit.

## Signing every other app→backend request
Headers:
```
X-RR-Install:    <install_id>
X-RR-Timestamp:  <unix seconds, UTC>
X-RR-Signature:  <base64url( ECDSA-P256-SHA256 signature, IEEE P1363 r||s, 64 bytes )>
```
Signing string (UTF-8, `\n` = LF, no trailing newline):
```
<METHOD uppercase>\n<URL path, no query>\n<X-RR-Timestamp>\n<lowercase hex SHA-256 of the raw body bytes; SHA-256("") for empty bodies>
```
Example: `POST\n/api/ingest\n1787310000\n3a7bd3e2…`

Server rules: timestamp within ±300 s of server time; install must exist and not be revoked; signature must verify against the stored key. Any failure → `401 {ok:false,error:"Invalid install signature."}` (missing headers on a route that requires signing → 401 too). A stable per-event `event_id` in telemetry metrics makes retries idempotent.

## Which routes
| Route | Signature |
|---|---|
| `POST /api/ingest`, `POST /v1/telemetry/event` (worker + Pages) | required, **or** legacy key while `LEGACY_INGEST_KEY_ENABLED=true` (rows tagged `ingest_auth_mode='legacy_key'`) |
| `POST /api/usage/consume`, `GET /api/usage/status` | required (no legacy clients use them) |
| `POST /api/feedback`, `POST /api/access/status`, `POST /api/license/validate`, `POST /api/license/activate` | verified if present; unsigned allowed (legacy clients) until `REQUIRE_INSTALL_SIGNATURE=true` |
| `GET /api/announcements/active`, `GET /api/discord/oauth-start` | no signature (public reads), rate-limited |

## Server-side binding
- Authenticated `install_id` overwrites `metrics.install_id`; `app_sessions.install_id` of an existing row must equal it, otherwise `403` — nobody can write into another install's session.
- `installs(install_id PK, public_key_jwk, hwid, app_version, created_at, last_seen_at, revoked_at, revoke_reason, license_id)`; admins can revoke; `last_seen_at` bumps at most once per 5 min.

## Client (C#, .NET 10) notes
`ECDsa.Create(ECCurve.NamedCurves.nistP256)`; export JWK via `ExportParameters(false)` → `Q.X`/`Q.Y` base64url; `SignData(bytes, HashAlgorithmName.SHA256, DSASignatureFormat.IeeeP1363FixedFieldConcatenation)`; private key persisted with `SecureStorage` (DPAPI) under `rr.install.key` as PKCS#8 base64. Test vectors: `tests/install-auth/fixtures/vectors.json` (generated by the server test-suite; the C# unit tests must verify the same vectors).
